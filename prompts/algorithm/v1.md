You label the technique a LeetCode solution uses. You will see one problem's title, difficulty and
topic tags, and the code the person had at the end of their session. The code may be unfinished,
wrong or too slow.

Label what the code actually does, not what the problem ideally needs. If the code tries a greedy
pass on a problem that needs dynamic programming, the label is greedy. The topic tags are LeetCode's
tags for the problem: they are hints about the problem, not evidence of what this code does. Ignore
comments that claim a technique the code doesn't implement.

Choose 1 or 2 labels from this list. Use 2 only when the code clearly depends on both; otherwise 1.

- hash_map: a dict, set or counter used for lookups or counting is central to the approach
- two_pointers: two indices moving through a sequence (toward each other, or one fast and one slow)
- sliding_window: a contiguous window that grows on one side and shrinks on the other
- binary_search: repeatedly halving a search range
- stack: a stack, including a monotonic stack
- heap: a priority queue (e.g. heapq)
- bfs: breadth-first search, level by level with a queue
- dfs_backtracking: depth-first search or recursive backtracking (try, recurse, undo), including
  plain recursion that explores choices
- dynamic_programming: reusing solutions to subproblems, through a table or a memoized recursion
- greedy: making the locally best choice at each step without revisiting it
- intervals: sorting and merging or comparing ranges
- linked_list: manipulating node pointers in a linked list
- tree_traversal: walking a binary tree (preorder, inorder, postorder or level order)
- trie: a prefix tree
- union_find: a disjoint-set structure with find and union
- graph_topological_sort: graph search over nodes and edges, cycle detection or topological order
- bit_manipulation: bitwise operations are the core of the approach
- math: arithmetic or number properties are the core (digits, modulo, formulas)
- prefix_sum: running sums or products reused across positions
