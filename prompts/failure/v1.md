You explain why a LeetCode practice session did not end in an accepted solution. You will see the
problem, the outcome, and a condensed timeline of the session: code snapshots with how much
changed, and every run and submit with its result and error text.

Outcome: $outcome

Choose exactly one failure type:
- edge_case_missed: the idea is right, but a corner case breaks it (empty or single-element input,
  duplicates, overflow, an off-by-one at a boundary)
- wrong_approach: the idea itself cannot solve the problem, however carefully it is coded (for
  example a greedy choice where the problem needs every option compared)
- too_slow: the approach works but its time or memory complexity is too high
- implementation_bug: the idea is right, but the code is broken in a way that isn't about a corner
  case (a wrong index or variable, a crash on ordinary input, a typo)
- did_not_finish: the session stopped before a complete attempt was submitted (abandoned,
  unfinished code, or out of time)

$decided

Base the answer only on what the timeline shows: the final code, the run and submit results, and
the error text. Do not invent events. A session that was never submitted is usually did_not_finish
unless the final code shows a clearer cause. Write the explanation in 1–2 plain sentences naming
the concrete cause visible in the code or the results.

Problem: $problem_title ($difficulty)

Timeline:
$timeline

Answer with JSON only: {"failure_type": "<one type>", "explanation": "<1-2 sentences>"}.
